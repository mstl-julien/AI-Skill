# 合规红线（采集与生成共用）

> 本 Skill 的一切行为以「普通访客/已登录用户在页面上能看到的公开信息」为边界。
> 这些红线在采集层由代码硬闸门执行，在分析层由纪律执行，两侧都不可绕过。

## 1. 采集侧（代码已强制）

- **只采公开展示字段**：接口原始响应含 150~430 个字段，白名单闸门只放行页面公开展示的；
  其余丢弃并留痕（`collection_log.json → dropped_fields`）。
- **永不采集**（接口给了也不采）：播放量 `play_count`、推荐数 `recommend_count`、
  赞赏数 `admire_count`、码率 `bit_rate`、播放/下载地址 `play_addr`/`download_addr`、
  平台风控字段 `aweme_control`、作者内部 ID `uid`/`sec_uid`。
- **不推断**：不根据头像/简介/内容推断账号主年龄、性别、所在城市；不推断团队规模、营收。
  `profile_age` 类字段只有页面公开展示才采。
- **不编造**：接口没给的字段标 `UNAVAILABLE`，页面上不存在标 `NOT_VISIBLE`，都不填 0。
- **被动监听**：数据来自浏览器自身发出的请求响应（XHR 被动监听），不构造签名、不重放请求、不逆向算法。
- **禁做项**（Spec §24，V0.1 明确不做）：数据库、代理池、并发采集、自动过验证码。

## 2. 运行侧

- **登录态**：访客态不报错、只安静地少给数据（作品卡第一页、评论砍到 5~10 条）。
  正式采集必须登录态；未登录时程序会警告，分析层应拒绝消费访客态数据做对标结论。
- **频率**：滚动/翻页带随机延迟，不并发、不多开。出现验证码（`CAPTCHA`）立即停止，不重试绕过。
- **数据目录**：运行产物（data/ browser-profile/ report/）一律落 `DC_HOME` 指定的工作目录；
  `browser-profile/` 含登录 Cookie，不得提交仓库、不得复制分享。

## 3. 分析/输出侧

- 播放量、完播率、GMV、转化率、粉丝画像等**非公开维度一律不出现在结论里**。
- 「对标」只对标公开可见事实：账号信息、作品四项互动、标题话题、时长、发布时间、公开评论。
- 引用评论原文时保留原样（含错别字），注明昵称与获赞数，不拼接、不改写、不化名影射。
- 报告中凡属分析推断（钩子类型、迁移逻辑、选题建议）必须显式标注，与数据事实区分。
