# 对标分析框架（分析层）

> 分析层只消费采集层落盘的结构化数据。**先读 `references/data-dictionary.md`，再写任何结论。**

## 0. 硬性纪律

1. **每个结论必须能指回具体字段**。格式：结论后跟 `(依据: videos.json.likes 分位数 / account.json.follower_count)`。
2. **禁止编造**：字段缺失就写「未采集/不可见」，禁止填 0、禁止猜测。
3. **禁止推断**：不推断账号主年龄/性别/团队规模/营收；`identity_text` 只做抄录不做演绎。
4. **播放量/完播率/GMV 维度直接不写**——属非公开数据（见 data-dictionary §5），写了就是编造。
5. 区分「事实」与「假设」：所有超出数据范围的推测必须显式标注「假设，待验证」。

## 1. 报告结构（对标账号 → 可执行选题）

```
一、账号基本盘        —— account.json
二、内容结构          —— videos.json + video_details.json
三、爆文要素拆解      —— 代表视频中高点赞项的标题/话题/时长
四、评论区洞察        —— comments.json
五、与自身账号的差距   —— 需要提供自身账号数据；没有则此节标"缺自身数据"
六、可迁移的选题清单   —— 落到可直接开拍的选题，不是泛泛的"方向"
```

## 2. 各节的取数与写法

### 一、账号基本盘（取数：account.json）
- 昵称 / 抖音号 / 粉丝数 / 获赞 / 关注数 / IP 属地 / 企业号与认证（区分两个概念）
- 简介 `bio` 原文抄录 + `identity_text`（有则抄，无则写"简介无身份自述"）
- 内容结构 `content_structure`（有哪些 tab、作品总数）
- 平均赞粉比 = `total_likes / followers_count`（用 account.json 两个现成字段相除，注明是计算值）

### 二、内容结构（取数：videos.json）
- 作品点赞分布：中位数 / P90 / 最高，标注样本量。
  全量采集完成（`homepage_meta.has_more=0`）时可写「基于全部 N 条作品」；
  `has_more=1` 时必须写「基于已采 N 条，未到列表尽头」。
- 置顶策略：`is_pinned` 的条目点赞量与普通条目对比
- 发布节奏：`publish_time` 的时间间隔分布（注意样本是抽样，跨度大时只说"跨度"不说"频率"）
- 内容形态：`aweme_type` 分布（0=普通视频，68=图集，163=图文 等）

### 三、爆文要素（取数：video_details.json，按 likes 排序取 Top 5~10）
逐条列出：标题原文 / 话题标签 / 时长 / 四项互动 / 发布时间。
只做**模式归纳**（标题句式、话题组合、时长区间），每条模式注明覆盖了几条样本。
标题中的钩子类型（数字型/悬念型/身份代入型）属于**分析判断**，需标注"分析推断"。

### 四、评论区洞察（取数：comments.json）
- 先声明样本口径：每条视频抽 20~50 条、按页面顺序（非全量），覆盖率见 `comments_coverage_pct`
  （注意：分母 total 含楼中楼回复，见 data-dictionary §2.1）
- 高赞评论 Top 10（昵称/内容/获赞/IP）
- 关键词聚类：人工归纳高频词（如"怎么学""多少钱""求教程"），
  每个词标注出现次数与所属视频
- 诉求信号：评论里出现"求教程/求链接/怎么报名"类 → 记录条数与占比，这是转化线索
  （占比 = 出现条数/该视频已采评论数，必须写明分母）
- 情感倾向只做粗分（正向提问/负向吐槽/中性），不做打分模型

### 五、与自身账号的差距
- 需要用户提供自身账号的采集数据（跑一次本 Skill 即可）
- 只对比**双方都有的公开字段**：赞粉比、更新跨度、标题钩子、话题标签、评论区诉求
- 缺自身数据时整节写「缺自身账号数据，无法对比」，不得用印象填

### 六、可迁移的选题清单（最终交付物，最重要）
- 每条选题给出：选题名 / 参考对标视频（video_id）/ 迁移逻辑（为什么适用于自身账号）/
  建议形式（口播/字幕驱动/实拍）
- 选题数量 5~10 条，宁少勿滥；每条都要能追溯到对标证据

## 7. 多账号对照

用 `tools/compare-accounts.js` 生成 25 项指标对照表，重点看：
- `作品采集比例`（受 --max-videos 限制，非质量问题）
- `评论未采完（异常）`——**任何账号 >0 则该账号数据不可信，先重跑再分析**
- `评论停止原因分布`——LIST_EXHAUSTED 多说明该号评论本来就少（小号正常）
- `aweme_type 分布`——出现 68/163 说明有图集/图文，对标选题时要分开看
