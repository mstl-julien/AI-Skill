# 多元素语义失效与逻辑控制

> 来源：90 提供深度授课资料，2026-09-28 沉淀。
> 定位：多元素画面（人物+道具、多产品、主体+配景）的**失效诊断与绑定控制**。与既有体系的关系：三段论管结构组织，槽位理论管"模型会补什么"（见 `subject_environment_medium_guide.md` 第五节），本文件管"模型会错什么、怎么锁"。
> **理论接口**：槽位理论指出先验补全发生在"已指定类别内的未指定槽位"；本文的"先验覆写"是同一机制的反面——强先验场景（如"咖啡馆"自带杯具人群）会挤入画面，**抢占弱元素的槽位**。

---

## 一、语义失效五类 Taxonomy

| 失效类型 | 定义 | 示例 |
|---|---|---|
| **属性串色** | A 的颜色/材质迁移至 B | 机器人金属色染上收音机木壳 |
| **元素融合** | 两元素边界消失，合为一体 | 机器人手臂与收音机外壳粘连 |
| **语义遗漏** | 某元素整体未渲染 | 墨镜消失 |
| **属性错配** | 属性绑定至错误主体 | 墨镜戴在旁观者脸上 |
| **计数错误** | 数量不符 | 收音机变为两台 |

---

## 二、失效机制（为什么错）

- **注意力竞争**：长文本中元素争夺权重，弱元素被挤出渲染。
- **相似 token 干扰**：共享修饰语的两元素最易串色——"红色的机器人和收音机"→ 颜色归属歧义。
- **语序效应**：首因区（句首）与近因区（句尾）权重高，中段为稀释区（同方法论文件第四节"注意力权重衰减"）。
- **先验覆写**：强先验（"咖啡馆"自带杯具人群）挤入画面，挤占弱元素槽位。

---

## 三、控制工具箱（按优先级）

1. **绑定句法（首选）**：一元素一句，属性紧随其主、不出本句；以所属结构绑定（"机器人面部戴着一副墨镜"而非"墨镜和机器人"）；**杜绝跨句共享修饰语**。
2. **分离声明**：显式写入"二者相互独立、互不融合、互不染色"，为模型提供边界指令。
3. **语序策略**：主体置首因区；次重要元素置第二句或句尾近因区；**中段稀释区仅放环境层**。
4. **强调机制（千问特化）**：以自然语言强调为主（"尤其是""画面核心为""务必呈现"）；括号权重符号（如 `(关键词:1.5)`）为 SD 系语法，千问平台多数不支持——若确支持，仅对单一元素慎用，避免全局权重失衡。
5. **负面提示词**：优先使用平台独立负面字段，枚举不欲之物（元素融合、多余肢体、文字水印）；**忌在正向句内写否定**（"不要红色"可能反向激活红色概念）。
6. **计数与空间化**：数值＋逐一定位（"共两件：其一……其二……"），以空间槽位锁定数量。
7. **兜底手段**：分阶段生成（先主体后环境）、局部重绘修复残差。

---

## 四、绑定句式公式

**元素名词 ＋ 所属属性簇 ＋ 空间位置 ＋ 独立声明**

示例：

> 一台银灰色拉丝金属机器人，面部戴着一副黑色墨镜（墨镜仅属于该机器人）；其面前的木桌上独立放置一台复古收音机，木质箱体配黄铜旋钮；机器人与收音机相互独立、互不融合；咖啡馆环境……

---

## 五、适用时机（防过度工程）

单主体简单画面**无需**全部启用——过度绑定徒增 token 冗余、稀释权重（同"冗余稀释"法则）。

**触发条件**：画面含 ≥2 个独立元素，且存在共享颜色/材质/空间关系风险时，按工具箱优先级逐级启用。

---

## 六、验证协议（2026-09-28 沉淀）

- **n=1 警示**：单次首渲零失效是强证据但**不是成功率**。长期标准：一次性成功率 ≥70%，须经**多种子重复测量**方可报告。单轮零失效只能写"本次无失效"，不可写"该句法成功率 100%"。
- **消融实验**：保险层（分离声明/负面清单）是否真有效，需**消融验证**——移除绑定句法后观察保险层能否 rescue 失效画面。单轮保险层空转仅能证"未必需"，不能证"无效"。两层各自的价值必须独立测量。
- **无种子工具链的降级方案**：同 Prompt 连续重渲 N 次（每次种子随机且不可记录，以文件名时间戳区分），按五类 taxonomy 逐张核验后统计失效频次——这是无种子条件下的近似多种子协议。
- **⚠️ 串行强制**：多次生成必须**串行执行**——并发调用会因文件名时间戳精确到秒而互相覆盖（实测：4 并发只落盘 3 文件，n=4 静默变 n=3）。每张落盘确认后再渲下一张；渲染完成后核对实际文件数与调用数一致。

> **多种子验证的完整工作流落点**（封面/系列图项目级任务）：n=4 次生成、成功率 ≥3/4 达标线、成功定义、提示词级迭代替代 inpainting、版本变更留痕——见 `project_workflow.md` 阶段 4。
