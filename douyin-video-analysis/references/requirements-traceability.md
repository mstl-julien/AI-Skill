## 批次 1（2026-09-24 上）：抽帧规则按 V3 规范优化

**需求原文**：用户给出《通用关键帧抽取规则_V3.md》（最初给豆包云盘链接，实测「暂无权限」→ 改为落到工作区根目录）。
要求按该规范优化抽帧采样。

**规范与旧实现的本质差异（被规范 §9 点名批评两条反模式）**

| 维度 | 旧实现 | 规范 V3 |
|---|---|---|
| 比较对象 | 与「上一个保留帧」比 | 与**场景锚点**比（场景内不更新） |
| 硬切检测 | 复用 SSIM<0.5 深谷 | 独立通道：直方图巴氏距离 |
| 软变化阈值 | SSIM **0.05** | 真 SSIM **0.93** |
| 冷却窗/事件上限/长镜兜底 | 无 | 有（2.0s / 2 帧 / 8.0s） |
| 类型参数档 | 无 | 5 档 |

**★ 两项工程校准（实测得出，非拍脑袋，必须保留）**

① **硬切阈值量纲校准**
- 规范 `HARD_CUT_TH=0.85` 是理论区间写法；实测标准巴氏距离 `sqrt(1-Σ√(h1·h2))`
  在实拍快剪视频上 max 仅 **~0.46**、p95≈0.30 → 直接套 0.85 永不触发（场景数退化为 1）。
- 改自适应分位：`cut_th = max(p95, 0.85×max×0.6)`。
- **交叉验证**：视频2 p95=0.3069 → **17 硬切点**，与完全独立的信号（10FPS 细采样 SSIM<0.5 深谷）
  检出的「17 镜」**完全一致**。双通道互相印证。

② **SSIM 档位标定**
- 规范 `SSIM_KEEP_BELOW=0.93` 按静态机位标定；实测手持实拍视频：同镜头内相邻 1/3 秒帧 SSIM 仅
  **0.53~0.61**，场景内相对锚点中位数低至 **0.17**。
- 结论：**软变化通道在抖音手持动态实拍（占带货视频绝大多数）上无区分度**，任何阈值结果都「几乎所有帧判为事件帧」。
- 处理：按机位动态性分档（静态 0.93 / 通用 0.85 / 动态 0.55），并加运行时自检输出
  `ssim_channel_effective=false` 如实标注。另验证 pHash（规范 §5.3 备选）：场景内中位数 28 vs 跨场景 32，区分度同样极差。
- **明确结论**：这类视频主力必须是「硬切 + 冷却窗 + 事件上限」。

**落地文件**：`scripts/keyframe_select.py`（V3 状态机重写）、`scripts/rebuild_timeline.py`（关键帧变更后重建时间轴）、
`references/keyframe-spec-v3.md`（规范原文归档）、SKILL.md 铁律 3 重写。
**验证**：视频2 340帧/113s → 46 关键帧 / 18 场景（17 硬切 + 27 事件 + 首末），密度 24.4/分钟（规范 10~40），
§8 七项自检全过，报告 173 图 0 加载失败。

## 批次 2（2026-09-24 中）：脚本文案公式 + 封面直解

**需求原文（两条）**：
1. 之前案例明确要求「复制与迁移」中添加脚本文案公式，本案例没加——**以后所有分析案例必须添加**。
2. 视频封面抽取有误：不要用抽帧法，直接抽取视频**第一帧**作为封面。

### 铁律 5 — 24 章必须含脚本文案公式
- **根因**：`render_replication` 里 `script_formula` 是可选字段，数据缺失时 `if sf:` 静默跳过 → 24 章无公式。
- **修复**：改为**强制区块 + 兜底推导**。`default_script_formula(rep, analysis)` 数据缺失时按案例特征
  （one_line / directly_copyable / hook / emotion.curve）自动生成五槽位通用骨架，报告打「自动推导」橙色徽章并明示来源。
- **踩坑**：`emotion.curve` 是对象列表 `[{stage,emotion,evidence}]`，直接 str() 会渲染成裸 dict →
  改为取 `stage（emotion）` 拼装（「建立（好奇）→ 放大（愉悦）→ ...」）。
- **要求**：分析阶段应主动产出真实公式，不依赖兜底；显示「自动推导」即表示漏产出。

### 铁律 6 — 封面 = 视频文件第 1 帧直接解码
- **根因**：`render_click` 用 `frame_at(0.0, frames_dir)` 从**抽帧目录**取首帧。
- **实测证据**：独立直解 cover.png 与 frames3/f_00001.jpg 对比 → **SSIM 仅 0.7628、平均像素差 17.33**（确实非同一帧）。
- **修复**：新建 `scripts/extract_cover.py`（ffmpeg `select=eq(n,0)` 直解 frame_index=0，无损 PNG + 元信息 JSON，带 `-ss 0` 兜底）；
  `render_click` 新增 `cover_rel` 参数优先引用 `cover.png`，找不到才回退抽帧首帧且**橙色标注回退原因**。

## 批次 3（2026-09-24 下）：章节按编号排序

**需求原文**：报告中每个章节的排列顺序，请按标题的标号进行排序。

**根因**：各分析章节分散在多个渲染函数里拼接，**拼接序 ≠ 编号序**（如「25 互动结构」被拼到「05」后、「06 点击前分析」拼到「21」后）。

**落地**：`build_report.py` 新增 `reorder_cards_by_number(doc)`（main() 写文件前调用）。
`_chapter_sort_key(title, orig)` 按 `<h3>` 前缀编号 `\d+[a-z]?` 生成三元组（`07b`→major=7,minor=20；`15a`→15.10）；
无编号系统卡查 `_ANCHOR_SLOT` 锚定到宿主章节之后（关键帧与机器分析=4.5 / keyframe_timeline=13.5 / voiceover=17.5 / CTA 与互动机制=21.5）；
未识别→98 靠后且保留原序。`_split_top_level_cards(body)` 用 card 起点锚定 + div 深度配对切出顶层 card 序列后重排拼回。

### ⚠️ 三起事故与教训（维护者必读）

**事故 1：编辑把 build_report.py 改坏**
误删 main() 尾部收尾代码、插入重复 `def main():`、切断 `linkify` 函数体 → `line 1183 unexpected indent`。
已逐项补回（收尾 + linkify 完整函数体），`ast.parse` 通过、无重复 main。
**教训**：改大文件前先备份，改完立刻 `ast.parse` 验证。

**事故 2：排序后 36 章节只剩 6 个（最致命）**
`_split_top_level_cards` 的 card 正则只写了双引号 `class="card"`，而实际有两种写法 ——
`block()` 产出 `class='card'`（**单引号**，16 处），doc 硬编码 `class="card"`（**双引号**，9 处）。只匹配一种 → 大量 card 被静默丢弃。
**修复**：`re.compile(r'''<div\b[^>]*class=['"]card['"]''')`。
**教训**：HTML 里同一类元素的引号写法可能不统一，切分正则必须同时兼容两种引号。

**事故 3：验证脚本自己错了（虚惊）**
用 `re.findall(r"<h3[^>]*>(.*?)</h3>", doc, re.S)` 取标题会误匹配 `<script>` 块内文本，导致误报乱序。
**修复**：先按 card 切分，再在各 card 段内取 h3。
