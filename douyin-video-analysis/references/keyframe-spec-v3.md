# 通用关键帧抽取规则（V3）

> 版本：V3.0 ｜ 用途：作为 Skill 内嵌的视频抽帧规范，供 Agent 集成到现有视频理解/报告生成流水线。
> 适用范围：所有时长、所有类型的视频（口播、快剪、教学、监控、延时、广告等）。
> 本规则不绑定任何具体视频内容、具体时间戳或具体镜头数。

---

## 1. 目标

从视频中抽取一组**最小且充分**的关键帧，送入下游模型推理生成报告。

- **最小**：不送近重复帧、不送同镜头内的微动作帧；
- **充分**：不遗漏任何真实镜头切换，不遗漏场景内有信息增量的变化帧。

约束：OCR/字幕文本**不得用于"提升"关键帧**（即不得仅凭文字变化就新增关键帧），仅可用于"丢弃"确认（见 §6.4）。

---

## 2. 术语

| 术语 | 定义 |
|---|---|
| 采样帧 | 按固定 FPS 从原视频均匀取出的候选帧，绑定时间戳。 |
| 硬切（hard cut） | 两个相邻采样帧之间发生了镜头切换，由确定性信号判定，不依赖软阈值。 |
| 场景（scene） | 两个相邻硬切之间的视频片段。 |
| 场景锚点（anchor） | 一个场景内的第一帧灰度图；场景内所有软变化判定都与它比，而不是与上一个保留帧比。 |
| 事件帧（event frame） | 同一硬切场景内，相对锚点发生了结构性变化而被额外保留的帧。 |
| 冷却窗（refractory） | 保留一帧后，在该时间窗口内不再因软变化新增帧（硬切除外）。 |
| 真 SSIM | 取值 0~1，**1 = 两帧完全相同**，0 = 无结构相似。集成时必须确认管道输出的是真 SSIM 还是 `1−SSIM` 差异量（见 §5.3）。 |

---

## 3. 输入 / 输出契约

### 输入
- 视频文件路径或可读帧流；
- 可选：视频类型提示（`talking_head` / `fast_cut` / `static_monitor` / `tutorial` / `generic`），用于选择参数档（§7）。

### 输出
关键帧列表，每帧至少包含：
```
{
  "timestamp_sec": float,      // 秒，相对视频开头
  "frame_index": int,          // 原视频帧号
  "frame_bgr": <image>,        // 解码后的帧
  "keep_reason": "first" | "hard_cut" | "event" | "long_scene_midpoint" | "last"
}
```
被过滤掉的帧**不进入下游模型**，不出现在报告里。报告可附带保留帧的 OCR 文本作为展示信息，但 OCR 不影响保留决策。

---

## 4. 算法流程（状态机）

按顺序执行；每一步的输出是下一步的输入。

```
采样 → [首帧强制保留] → 逐采样帧循环：
  ├─ A. 硬切检测
  │     是硬切 → 开新场景：当前帧成为新锚点，强制保留，重置场景内计数，进入下一帧
  │     否     → 继续
  ├─ B. 冷却窗判断
  │     距上一保留帧 < REFRACTORY_SEC → 丢弃，进入下一帧
  │     否则 → 继续
  ├─ C. 与场景锚点比软变化（真 SSIM 或 pHash）
  │     与锚点差异足够大 → 视为事件帧：
  │         若本场景事件帧计数 < MAX_EVENT_PER_SCENE → 保留，计数+1
  │         否则 → 丢弃
  │     与锚点几乎一样 → 丢弃，进入 D
  └─ D. 长镜头兜底
        若本场景已超过 LONG_SCENE_SEC 且尚未补过中点锚点，
        且距上一保留帧 ≥ REFRACTORY_SEC → 保留当前帧作为中点锚点
末帧强制保留（若与最后一保留帧间隔 > 0.5s）
```

**关键不变量（必须在实现中保证）：**
1. 场景锚点一旦在场景首帧设定，**整个场景内不更新**；所有软变化判定都对它做。
2. 硬切判定走独立通道（§5.1），**不**复用 SSIM 软阈值。
3. 冷却窗对软变化生效，**对硬切不生效**（硬切永远保留）。
4. 一个场景内：1 个锚点帧 + ≤ MAX_EVENT_PER_SCENE 个事件帧 + 可选 1 个中点锚点。

---

## 5. 各步骤规范

### 5.1 采样
- 默认 `SAMPLE_FPS = 3`（即每 1/3 秒取一帧）。
- 运动密集/快剪类视频可升到 `SAMPLE_FPS = 5`；静态监控/延时类可降到 `1`。
- 采样帧必须绑定 `timestamp_sec`，不得只存帧号。

### 5.2 硬切检测（确定性，前置步骤）
- 对**相邻两个采样帧**的灰度图计算：
  - 直方图巴氏距离（推荐，便宜稳健），或
  - 边缘变化率（ECR），或
  - 相邻帧全局 MSE 的突变倍数。
- 判定：巴氏距离 > `HARD_CUT_TH` 即判硬切。
- 硬切触发时无条件保留当前帧，并开启新场景。
- **禁止**用 SSIM 软阈值来判硬切。

### 5.3 场景内软变化判定
- 比较对象：当前采样帧 vs **场景锚点**（不是上一保留帧）。
- 计算指标二选一：
  - **真 SSIM**（推荐）：`ssim = structural_similarity(anchor_gray, current_gray)`，统一缩放到相同尺寸。
  - **pHash 汉明距离**：对两帧 32×32 灰度图算 DCT 感知哈希，取汉明距离。
- 判定规则（**方向不能写反**）：
  - 用真 SSIM（1=相同）：`ssim < SSIM_KEEP_BELOW` → 有变化，考虑保留；`≥ SSIM_KEEP_BELOW` → 近重复，丢弃。
  - 用 pHash（bit 差异数，0=相同）：`hamming > PHASH_KEEP_ABOVE` → 有变化；`≤ PHASH_DROP_BELOW` → 丢弃。
  - **若管道输出的是 `1−SSIM` 差异量（0=相同）**：必须换算成真 SSIM 再按上面规则判断，禁止直接拿 0.05 这种小数当阈值。
- 两种指标之间留一个死区（hamming 在 6~8 bit 之间 / SSIM 在 0.90~0.93 之间）时，默认丢弃，避免抖动。

### 5.4 冷却窗与场景上限
- `REFRACTORY_SEC`：保留一帧后，该时长内不再因软变化新增帧。
- `MAX_EVENT_PER_SCENE`：单场景锚点之外最多保留的事件帧数。
- `LONG_SCENE_SEC`：单场景时长超过此值且全程无软变化 → 在其中点补 1 个锚点帧，且只补一次。

### 5.5 OCR 边界
- OCR **不得**用于决定"新增关键帧"。
- OCR **可以**用于决定"丢弃候选帧"：当候选帧与锚点在视觉上已是近重复、且 OCR 文本完全一致时，强制丢弃（这只是抑制，不会新增帧）。
- 保留帧的 OCR 文本可作为附加信息随帧输出，供报告展示。

### 5.6 首末帧
- 视频第一帧和最后一帧强制保留，不受任何软阈值/冷却窗限制。
- 若末帧与最后一保留帧间隔 ≤ 0.5s，则不重复保留。

## 6. 参数默认值与取值范围

| 参数 | 默认值 | 合理范围 | 作用 |
|---|---|---|---|
| `SAMPLE_FPS` | 3 | 1 ~ 5 | 候选帧采样密度 |
| `HARD_CUT_TH` | 0.85（巴氏距离） | 0.70 ~ 1.0 | 硬切灵敏度；调小→切点召回高但易误判 |
| `SSIM_KEEP_BELOW` | 0.93 | 0.90 ~ 0.95 | 与锚点相比，结构变化超过 (1−阈值) 才保留 |
| `PHASH_KEEP_ABOVE` | 8 bit | 6 ~ 12 bit | pHash 方案的"有变化"下界 |
| `PHASH_DROP_BELOW` | 6 bit | 4 ~ 7 bit | pHash 方案的"近重复"上界 |
| `REFRACTORY_SEC` | 2.0 | 1.0 ~ 3.0 | 软变化冷却窗 |
| `MAX_EVENT_PER_SCENE` | 2 | 1 ~ 3 | 单场景事件帧上限 |
| `LONG_SCENE_SEC` | 8.0 | 6 ~ 15 | 长镜头补中点锚点阈值 |

**调参顺序（在任意新视频上）：**
1. 先保证硬切召回：用人工标注的若干个切点检查是否全部命中；漏切点 → 调小 `HARD_CUT_TH`。
2. 再控冗余：若同镜头内仍出现连续近重复帧 → 调小 `SSIM_KEEP_BELOW`（更严格）或调大 `REFRACTORY_SEC`。
3. 最后补信息：若场景内明显有信息变化（如演示步骤切换、物体状态改变）却没出帧 → 调大 `MAX_EVENT_PER_SCENE`。

---

## 7. 按视频类型的参数档

集成时若能从输入识别类型，按下列档位取默认值；识别不出来就用 `generic`。

| 类型 | SAMPLE_FPS | REFRACTORY_SEC | MAX_EVENT_PER_SCENE | 说明 |
|---|---|---|---|---|
| `talking_head`（口播/访谈） | 2 | 2.5 | 2 | 镜头少、动作小，重点去微动作冗余 |
| `fast_cut`（快剪/MV/广告） | 5 | 1.0 | 2 | 硬切密，冷却窗要短，避免漏切点之间的内容 |
| `tutorial`（教学/操作演示） | 3 | 2.0 | 3 | 步骤切换是关键信息，事件帧上限放宽 |
| `static_monitor`（监控/延时） | 1 | 5.0 | 1 | 几乎全静态，只在异常变化时出帧 |
| `generic`（默认） | 3 | 2.0 | 2 |  |

## 8. 验收标准（集成后自检）

Agent 把本规则集成进 Skill 后，应在以下自检全部通过才算完成：

1. **切点召回**：在至少 3 段不同类型视频上，人工标注的硬切点 ≥ 95% 被保留为关键帧。
2. **无近重复**：任意两个保留帧之间，若不是硬切相邻，则它们之间的真 SSIM 必须 < `SSIM_KEEP_BELOW`（即不允许两个近重复帧都被保留）。
3. **密度合理**：1 分钟视频输出关键帧应在 **10 ~ 40 帧**区间；若 > 60 帧，判定为冗余过多；若 < 5 帧，判定为漏帧。
4. **冷却窗生效**：除硬切相邻帧外，任意两个保留帧的时间间隔 ≥ `REFRACTORY_SEC`。
5. **场景内计数**：任意非硬切场景内，事件帧数 ≤ `MAX_EVENT_PER_SCENE`。
6. **OCR 边界**：保留决策日志中不得出现"因 OCR 文本变化而新增帧"的记录；OCR 只可出现在"丢弃确认"分支。
7. **首末帧**：视频首帧和末帧都在保留列表中（或末帧与最后一保留帧 ≤ 0.5s 的合并情况）。

---

## 9. 反模式（禁止事项）

- ❌ 把软阈值 `0.05` 这种量级直接当 SSIM 用——真 SSIM 的近重复值在 0.9+，0.05 是差异量区间，量纲必须先对齐。
- ❌ 每个候选帧都只跟"上一个保留帧"比——会导致慢动作/慢摇镜头链式漏过（每步都"微变"，连起来是一串近重复帧）。必须跟**场景锚点**比。
- ❌ 用同一个 SSIM 阈值同时判硬切和软变化——硬切用确定性信号（直方图/ECR），软变化用 SSIM/pHash，两者通道分开。
- ❌ 因为 OCR 字幕变化就新增关键帧——OCR 只能用于丢弃确认。
- ❌ 在冷却窗内因微小 SSIM 抖动加帧。
- ❌ 把被过滤掉的帧也送入下游模型——只送保留列表。
- ❌ 忽略采样率口径不一致（规则写 3 FPS，线上跑 10 FPS 会让帧量差 3 倍）——集成时必须从实际编码器读 FPS，不要硬编码。

---

## 10. 输出给下游的元数据

每个保留帧建议附带：
- `timestamp_sec`、`frame_index`、`keep_reason`；
- `scene_id`（从 0 递增）；
- 该帧相对场景锚点的 SSIM 或 pHash 值（用于审计为什么这帧被保留）；
- 可选：OCR 文本（仅展示，不影响决策）。

下游报告生成器只消费 `frame_bgr + timestamp_sec + OCR(可选)`，不关心内部阈值。
